# Proposal: Agent Delegation Over A2A

Let the CEO agent hand a task to a peer agent over A2A, as a policy-classified action, and have the CEO's task record carry the peer's terminal result. Today the CEO can record intents, get them classified, escalate, and message Telegram — but it cannot delegate work to anyone. The code that claims to do so is unreachable and would delegate to itself.

**Affected agent roles**: `ceo` (issues delegation), `engineer` (receives delegation). Any role granted the new action kind in `risk_policy` can delegate; the shipped `company.yaml` grants it to `ceo` only.

## Intent

The framework's premise is "the human talks to the CEO, the CEO runs the company". Without delegation there is no company — the CEO is a single agent with a Telegram button.

The current state is worse than "missing": it is misleading.

| Finding | Evidence |
|---|---|
| Delegation path is unreachable in production | `supervisor.go:236-242` picks `executeDelegation` only when `PolicyEngine == nil`; `wire.go:351` always sets it and `policy.NewEngine()` never returns nil. |
| Even if reached, it delegates to itself | `supervisor.go:426` resolves `roleOf(s.cfg.Addr)` — the supervisor's own name. No target parameter exists. |
| No A2A client exists in-repo | Only the server side (`transport/a2a/server.go`). Both adapters stub `ResolveAgent`/`SendMessage` with `errNotImplemented` and a comment ("provided by transport/a2a") that is false. |
| No happy-path test | Only `TestProviderFailureMarksFailed` exercises the branch, and `TestIntegration_CEODelegatesToWorkerOverRealWire` is misnamed: it calls the worker handler in-process and tolerates zero calls. |
| No peer directory | Each agent's listen URL (`srv.BaseURL()`, ephemeral port) is printed to stderr and discarded (`wire.go:375-376`). Nothing maps role or name to a URL. |

This change closes the gap end-to-end and removes the dead code so the repository stops lying about what it can do.

## Scope

### In Scope

- **Policy-classified delegation action kind** (`delegate_task`, name subject to spec), declared in `risk_policy` with `allowed_roles`. The policy engine fails closed on unknown kinds, so the declaration is mandatory, not optional.
- **MCP tool for delegation**, generated by the existing one-tool-per-policy-kind loop, whose input schema carries a `target` argument in addition to `body`. The handler still only records the intent; it never executes.
- **Narrow delegation port** in `core/port` (a single-method interface: send text to a peer, block until terminal, return output) plus a new `supervisor.Config` field. `port.Provider` keeps meaning "run a CLI subprocess".
- **A2A client** in `transport/a2a` built on `a2aclient.NewFromCard`, `agentcard.DefaultResolver`, and `AuthInterceptor` with the shared bearer token. It sets `SendMessageRequest.Tenant` so `tenantInterceptor` accepts the call.
- **Peer directory**: a role/name → base URL map populated in `cmd/company/wire.go` as each server binds, injected into the client. Lookup of an unknown or not-yet-started peer returns a clear error.
- **Supervisor routing**: on a Permitted (or Approved-after-escalation) delegation intent, `executeAction` routes to the delegation port instead of the gateway; the peer's terminal output is copied into the CEO task's output. Blocking wait is bounded by a timeout.
- **Honest interim behavior on a non-terminal peer**: if the peer's task comes back non-terminal (the peer escalated to `INPUT_REQUIRED`), the delegating task FAILS with an explicit error stating that the peer escalated and that chained approval is not yet wired, naming the peer's role and task id. It never hangs, never silently completes, and never fabricates a result. Chained approval itself is out of scope (below).
- **Dead-code removal**: delete `executeDelegation`, `roleOf`, and the `PolicyEngine == nil` branch. A nil `PolicyEngine` becomes an explicit configuration error at construction, never a nil-pointer panic. Remove `ResolveAgent` / `SendMessage` / `SendMessageStream` from `port.Provider` and the six `errNotImplemented` stubs — `executeDelegation` was their only caller.
- **Honest tests**: retarget `TestProviderFailureMarksFailed` to the provider-failure path it actually proves; rename or rewrite `TestIntegration_CEODelegatesToWorkerOverRealWire` so it drives a real A2A client against a real server and asserts the peer was contacted.
- **Prompts and config**: `agents/ceo.md` tells the CEO how and when to delegate; `company.yaml` declares the new kind. Whether `sw-engineer` gains its own system prompt is an open decision (see below).
- **`go.mod` hygiene**: `golang.org/x/mod` is required by `a2aclient/factory.go` and present in `go.sum` but absent from `go.mod`; it must be added as indirect.

### Out of Scope

Deferred to the follow-up change `agent-delegation-chained-approval` (design slices 7, 8 and 9;
that change depends on this one being merged first, and must land slice 9 before slice 7):

- **Chained approval** — a peer's own escalation parking the delegating task into a single human
  approval on the peer's task, with automatic resume. This change fails the delegating task with
  an explicit not-yet-wired error instead. Unreachable with the shipped `company.yaml`, which
  grants `telegram_send` to `ceo` only, so a peer's risky action is `HardDeny`ed, never escalated.
- **Awaiting-peer distinguishability** — marking a delegating task's `INPUT_REQUIRED` as "awaiting
  a peer" versus "awaiting your approval" in the persisted record and any derived SSE/UI surface.
- **Restart recovery of an awaiting-peer wait** — re-establishing (or honestly failing) a
  delegation wait across a process restart. No such wait state exists in this change.
- **Monitoring-UI aggregation across supervisors** — the UI stays bound to `runtimes[0]` (the
  CEO's supervisor), as today. A peer's `INPUT_REQUIRED` task is invisible, which is precisely why
  UI aggregation must precede chained approval in the follow-up.

These are known follow-ups from a previous session and MUST NOT be smuggled in either:

- Conversation history / multi-turn dialogue in the policy path. The CEO agent process has exited before classification; this change does not resurrect it.
- The opencode adapter's MCP permission gap.
- Making `Contacted()` tool-call-aware.
- `minLength` on the `body` schema.
- Streaming delegation (`SendMessageStream`). Blocking only (D1).
- Peer-to-peer delegation beyond one hop. Recursion policy is an open decision, not a deliverable.

## Capabilities

> Contract with `sdd-spec`. Existing names come from `openspec/specs/` (archived) and the still-active `provider-tool-use-action-intents` and `agent-startup-framework-foundation` changes.

### New Capabilities
- `agent-delegation`: delegation as a policy-classified action kind; blocking wait with timeout; result copied into the delegating task; failure semantics (peer error, timeout, unknown peer, non-terminal peer state).
- `a2a-client`: outbound A2A client — agent-card resolution, bearer auth via `AuthInterceptor`, tenant propagation, bounded blocking `SendMessage`.
- `peer-directory`: mapping from delegation target key to live base URL, populated at wire time, with fail-fast lookup for unknown or not-yet-bound peers.

### Modified Capabilities
- `agent-supervisor`: remove the `PolicyEngine == nil` delegation branch (nil becomes a construction error); add the delegation port to `Config`; route Permitted delegation intents to it; copy peer output into task output.
- `mcp-tool-server`: "One Tool Per Risk-Policy Action Kind" — the generated input schema is no longer `body`-only; delegation kinds require a `target` argument.
- `provider-adapter`: `port.Provider` drops `SendMessage`, `SendMessageStream`, `ResolveAgent`; adapters and `fake.Provider` drop their stubs.
- `risk-policy-engine`: no engine logic change. `company-as-code` gains the new kind in the shipped `company.yaml`; if the spec enumerates kinds, that is a delta.

## Approach

Reuse the existing pipeline end to end; add one new leg at the end of it.

```
CEO agent (claude CLI)
  └─ MCP tools/call delegate_task {target, body}   ← existing MCP server, new tool
       └─ intent sink → ActionIntent{Kind, Payload{target, body}}   ← existing
            └─ policy.Classify(kind, role)            ← existing (HardDeny / Escalate / Permit)
                 ├─ Escalate → INPUT_REQUIRED → human approves → resume   ← existing
                 └─ Permit  → executeAction
                      └─ NEW: Delegator.Delegate(ctx, target, body)      ← new port
                           └─ transport/a2a client → peer /invoke (bearer, tenant)
                                └─ peer supervisor runs its own agent → terminal Task
                      ← peer output copied into CEO task output; CEO task COMPLETED
```

Key choices, all inherited from the orchestrator decisions:

| Decision | Choice | Why |
|---|---|---|
| D1 Blocking | `Delegate` blocks until the peer task is terminal | One end-to-end flow now; streaming later. |
| D2 Policy-classified | Delegation is an `ActionIntent` kind like `telegram_send` | Risky delegation gets human approval for free via the existing escalation + resume path. No second execution path. |
| D3 Narrow port | New `port.Delegator` (name subject to spec), new `Config.Delegator` | `Provider` means "run a CLI"; overloading it produced six `errNotImplemented` stubs. |
| D4 Timeout | Default **10 minutes**, configurable at the composition root | A peer driving a real claude CLI takes minutes; a hung peer must not pin the CEO supervisor goroutine. On expiry: CEO task → FAILED with an error naming the peer and the timeout. |

**Honest limitation (D1, stated on purpose):** by the time the intent is classified, the CEO *agent process* has exited. The CEO agent never sees the peer's answer. Only the CEO *task record* carries it — visible to the human via the task store and monitoring UI. This is a delegation-with-result, not a conversation.

## Open Decisions for the Design Phase

These are real product/design questions. The proposal surfaces them; it does not decide them.

| # | Question | Options on the table |
|---|---|---|
| OD1 | Peer task escalates to INPUT_REQUIRED (e.g. engineer wants Telegram). Blocking wait returns non-terminal. | (a) CEO task FAILED; (b) CEO task also INPUT_REQUIRED, chained approval; (c) CEO task COMPLETED with output "peer awaiting approval" + peer task id. |
| OD2 | Target resolution key: `role` (`engineer`) or agent `name` (`sw-engineer`)? `company.yaml` proves name ≠ role, and multiple agents may share a role. | Role (matches policy vocabulary, ambiguous with duplicates) vs name (unambiguous, leaks topology into prompts). |
| OD3 | Registry population ordering: servers start sequentially in the wire loop. | Fail delegation with a clear "peer not registered" error; or two-phase startup (bind all, then publish directory). Never a nil map read. |
| OD4 | Does the peer need its own system prompt (`agents/engineer.md`)? `sw-engineer` has none today. | Ship a minimal prompt in this change, or leave it to a follow-up. |
| OD5 | Loop guard: may a peer delegate onward, and what stops A→B→A? | Hop counter in payload; policy denies `delegate_task` to non-CEO roles (already the shipped default); both. |
| OD6 | On timeout, cancel the peer's task via A2A `tasks/cancel` or let it run to completion on its own supervisor? | Cancel (clean) vs let-run (peer's work not lost). |

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Blocking wait holds the CEO supervisor goroutine; a slow peer serializes CEO throughput | High | Timeout (D4); document that delegation is one-at-a-time per CEO task. Streaming is the follow-up. |
| Removing `PolicyEngine == nil` branch breaks a test that relied on it | Medium | `TestProviderFailureMarksFailed` is the only one; it is retargeted, not deleted. RED must be observed first. |
| Removing A2A methods from `port.Provider` widens the diff beyond the review budget | Medium | Isolate as its own work unit / chained PR slice; it is pure deletion with zero production callers. |
| `a2aclient` bearer/tenant behavior differs from the stale comment in `integration_test.go:88-92` | Low | Verified against v2.5.0 in exploration; the real-wire test proves it. |
| `go.mod` missing `golang.org/x/mod` breaks the build once the client is imported | High (certain) | Add indirect requirement in the same commit that introduces the import. |
| Delegation intent classified as Permit while target is unknown → CEO task fails after approval | Medium | Validate target against the directory before classification, so a bad target is rejected at intent time. |
| Estimated authored change exceeds 400 lines | High | Delivery strategy is `auto-chain`; `sdd-tasks` must forecast and slice (suggested: dead-code removal → client + directory → supervisor routing + MCP tool + wiring + prompt). |

## Rollback Plan

Every slice is independently revertible because the shipped `company.yaml` gates behavior:

1. **Config-level rollback (no code change)**: remove `delegate_task` from `risk_policy`. The MCP tool is not generated, the policy engine fails closed on the kind, and no delegation can occur. The CEO behaves exactly as today.
2. **Code-level rollback**: revert the chained PRs in reverse order. The dead-code-removal slice can stay reverted-or-not independently — it has no production callers either way.
3. **Nil `PolicyEngine` construction error**: if any deployment relied on the nil branch (none known; `wire.go` always sets it), reverting the supervisor slice restores the old behavior.

No persisted data format changes; task records gain output text only.
